[daily-report-auto] EVTA 작업 일일 보고서를 작성한다.

- 입력: `{BODY}`. 하루(YYMMDD 07:00 ~ 다음 날 07:00, KST) 동안 이 저장소에서 돌아간 Claude Code 세션들의 기록이다.
  - 사용자 요청(`### 시각 [세션 id] 요청`)과 그 턴의 요약(`**시각 [세션 id] 결과**`)이 시간순으로 들어 있다.
  - 보드에서 돌린 실험 결과는 이 요약 안에 있다. 보드 실험은 이 PC에서 ssh로 돌렸다.
- 출력: `{OUT}`. 이미 있으면 덮어쓴다. 다른 파일은 만들거나 고치지 않는다. git commit도 하지 않는다.
- 형식 예시: `docs/dailyreport/vta_systolic/vta_systolic_요약_261027.md`. 먼저 읽고 같은 형식으로 쓴다.

규칙:
1. **첫 줄 제목:** `# 20YY-MM-DD EVTA systolic 요약: <그날 가장 중요한 결과 2~3개를 짧게>`. 날짜를 맨 앞에 쓴다.
2. **머리:** 그다음 줄에 기간을 쓴다. 세션 구분도 쓴다.
   - 세션 id 대신 내용을 보고 [PC] / [보드]처럼 알기 쉬운 이름을 붙인다.
   - 이름은 그 세션이 주로 작업한 곳으로 정한다. PC의 어느 branch인지, 보드 main인지 등이다.
3. **`## 시간순`:** 요청을 시간 순서대로 나열한다. 항목마다:
   - 굵은 줄에 `**시각 [세션] "사용자 요청 원문(길면 줄임)"**`을 쓴다. 이어진 짧은 요청은 `/`로 한 줄에 묶는다.
   - 아래에 그 턴에서 한 일의 요약을 넣는다. 원래 요약 문장을 가능한 한 그대로 쓰되 줄여서 2~6줄로 한다.
   - 그날 특히 중요한 것은 "중요:"로 표시한다. 예: 결정을 바꾼 발견, 버그, 틀렸던 판단의 정정.
   - 같은 결과를 여러 번 보고한 중간 메시지는 마지막 것 하나로 합친다. 반복하지 않는다.
   - 사용자 요청 없이 백그라운드 작업 결과만 보고한 턴은 굵은 줄에 그 결과 제목을 쓴다.
4. **성능 측정 표는 하나도 빼지 않는다.**
   - 대상: EVTA 시간, GOPS, 클럭 sweep, 타이밍(WNS/WHS/WPWS), 보드 검증 결과, 가동률 등.
   - 해당 항목 안에 표로 넣고, 표 바로 위에 어떤 실험인지 한두 줄로 설명한다. 무엇을, 어떤 방법·조건으로, 무엇과 비교했는지 쓴다.
   - 수치는 원문 그대로 옮긴다. 원문에 있는 주석(편차, 추정, 미확인)도 함께 옮긴다.
5. **여러 단계를 거쳐 다시 빌드·수정한 과정**(타이밍 수정 단계, 결함 수정 순서 등)은 표로 쓰고, 왜 그 단계를 거쳤는지 설명한다.
6. **마지막 `## 결정이 남은 것 (다음 날 07:00 기준)`:** 사용자의 답을 기다리는 것과, 그날 이미 결정된 것을 짧게 쓴다.
7. **분량:** 표를 빼면 1~3쪽 정도로 한다. 한국어로 쓰고, 코드·식별자·명령은 원래 형태를 그대로 둔다.
8. **사실만 쓴다:** 기록에 없는 내용은 만들지 않는다. 확인되지 않은 것은 원문처럼 "추정", "미확인"으로 쓴다.
